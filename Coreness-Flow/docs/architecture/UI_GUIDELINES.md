# UI Layer — архитектура и Design System

Единый ориентир для разработки интерфейса Coreness Flow: архитектура UI (Electron + React), стилизация и визуальный стиль. Документ задаёт **направление**, а не жёсткие правила — при необходимости можно отступать. Главное: согласованность и удобство.

**Стек:** Electron (main process) + React (frontend в `frontend/src/`). Связь с backend по WebSocket; контракт — actions и events API Bus (JSON).

**Референс по духу:** основной ориентир — **Perplexity** (чат, сайдбар, поле ввода, общая философия продукта). От **Cursor IDE** — отдельные приёмы (сайдбар, тёмная тема, табы).

---

## 1. Принципы архитектуры

- **Компоненты React** — отображение и ввод. Получают данные через props; общение с backend — через фасад протокола (actions/events), без прямого хардкода сообщений по коду.
- **Один фасад протокола** — константы действий/событий и вызовы в одном месте (например `src/protocol.js` или аналог), чтобы не размазывать строки по компонентам.
- **Без бизнес-логики во frontend** — вся логика на backend; frontend шлёт запросы и отображает ответы/события.

**Поток данных:**

```
UI → Backend:   компонент → protocol.call(action, payload) → WebSocket → backend
Backend → UI:   backend (emit) → WebSocket → подписчики events → обновление состояния/UI
```

---

## 2. Структура фронта

- **frontend/src/** — компоненты (Sidebar, TabBar, ChatView, SettingsView и т.д.), стили (CSS/модули), точка входа (App.jsx, main.jsx).
- **frontend/electron/** — main process: окно, запуск backend (`run_backend.py`), preload для кнопок окна (minimize, maximize, close).
- **frontend/public/** — статика (splash.html для сплеша при загрузке).

Один файл на компонент — обычная практика; при росте можно выделять подпапки по областям (chat/, settings/).

---

## 3. Добавление нового экрана/компонента

1. Создать компонент в `frontend/src/` (или подпапке). Данные — через props; вызов backend — через общий фасад протокола (action/event).
2. Подключить в маршрутизации/состоянии приложения (табы, сайдбар).
3. Стили: общие переменные/тема в CSS; компонент — классы или CSS-модули.
4. Если сценариям нужен доступ к UI (например отправка сообщения в чат) — плагин core (например chats) регистрирует действие с `api_bus.emit()` для доставки во frontend.

---

## 4. Переиспользование и паттерны

**Граница с backend:** весь обмен идёт через `api.js` (call/on) и `protocol.js` (константы действий/событий, фасад). Компоненты не обращаются к WebSocket напрямую и не хардкодят форматы сообщений — только вызовы из protocol. Так фронт остаётся изолированным: доработка контракта в одном месте; backend и фронт можно развивать раздельно.

**Общие элементы** стоит переиспользовать, чтобы сохранять единый стиль и не дублировать логику. При нехватке возможностей — расширять существующие (пропсы, варианты), а не создавать параллельные реализации.

- **Модальное окно:** компонент `Modal` (`components/Modal.jsx`). Оверлей, заголовок, тело; опционально кнопка «Копировать» и вариант (default, error). Для подтверждений — те же классы `modal-actions`, `modal-action--danger` в контенте. Использовать для диалогов подтверждения, «О приложении», любых блокирующих окон.
- **Выпадающее меню:** общий стиль через классы `app-dropdown`, `app-dropdown-item`; для фиксированного позиционирования — `app-dropdown--fixed`. Стили в `styles/dropdown.css`. Сайдбар (меню шестерёнки), таб-бар (контекстное «Переименовать»), список чатов (меню по «…») используют один паттерн; новый пункт меню — разметка с этими классами.
- **Воркспейс:** контент показывается в одной области (таб + content). Базовая рамка и тема задаются приложением; сложные экраны (чат) могут задавать свои правила внутри области, но общая структура (сайдбар, таб-бар, content) единая. В перспективе плагины смогут задавать правила отображения; новые экраны вставляются как воркспейсы с тем же каркасом.

**Структура файлов:** один компонент — один файл; при росте объёма логики или числа связанных компонентов — подпапка по области (chat/, settings/). Крупные монолитные файлы усложняют навигацию и контекст; разбиение по ответственности предпочтительнее.

---

## 5. Стилизация

- **Тема** — `frontend/src/styles/variables.css`: CSS-переменные (цвета, отступы, скругления, размеры). Один источник правок темы; остальные файлы ссылаются на `var(--color-*)`, `var(--space-*)`, `var(--radius-*)`.
- **Разбиение по смыслу:** `layout.css`, `title-bar.css`, `sidebar.css`, `tab-bar.css`, `chat.css`, `chat-messages.css`, `chat-input.css`, `chat-list.css`, `settings.css`. Подключение в `App.jsx`; глобальный сброс и импорт переменных — в `index.css`.
- **Консистентность:** новые стили используют переменные из variables.css; не дублировать значения из палитры в файлах компонентов.
- **Доступность:** контраст текста и фона, достаточный размер областей нажатия.

## 6. Design System

### 6.1 Концепция

Тёмная тема, чистый профессиональный интерфейс. Ориентир — Perplexity (по духу продукта и чату); приёмы из Cursor (сайдбар, табы). Минималистичные компоненты, акцент на читаемости.

### 6.2 Палитра (Dark Theme)

| Назначение | Значения |
|------------|----------|
| Фон приложения | `#1e1e1e` – `#202020` |
| Фон панелей/карточек | `#252525` – `#2d2d2d` |
| Hover / selection | `#2f2f2f` – `#353535` |
| Бордеры, разделители | `#3a3a3a` – `#404040` (тонкие) |
| Текст основной | `#e0e0e0` – `#ffffff` |
| Текст вторичный | `#9e9e9e` – `#b0b0b0` |
| Текст disabled | `#6e6e6e` |
| Акцент (кнопки, активное) | `#0066ff` – `#3b82f6` |
| Success | `#10b981` |
| Warning | `#f59e0b` |
| Error | `#ef4444` |

### 6.3 Типографика

- **UI:** Inter, SF Pro или системный (Segoe UI на Windows).
- **Моно (код, YAML):** JetBrains Mono, Fira Code, Consolas.
- Размеры: H1 20–24px, H2 16–18px, основной текст 14px, вторичный 12–13px, код 13px. Межстрочный интервал ~1.5.

### 6.4 Отступы и скругления

- Отступы: стандарт 16px, компакт 8px, между секциями 24px, минимальный gap 4px.
- Скругления: карточки/панели 8px, кнопки 6px, мелкие элементы 4px.

### 6.5 Layout

**Структура окна:** слева **сайдбар** (~200–240px), справа **область воркспейсов**: сверху **таб-бар** открытых вкладок, под ним **одна область контента** — активный воркспейс (чат, настройки и т.д.).

- **Сайдбар** — глобальные действия и навигация: новый чат, настройки. Пункты сайдбара вызывают действия (создать вкладку, переключиться на настройки).
- **Таб-бар** — список открытых воркспейсов. Переключение по клику; закрытие по крестику. Кнопка «+» — новый чат.
- **Область контента** — один активный таб: чат (сообщения прижаты к правому краю), настройки; в перспективе — вкладки плагинов (контент только внутри этой области).

### 6.6 Компоненты (ориентиры)

- **Sidebar:** фон `#252525`, пункты — иконка + текст, hover `#2f2f2f`, активный — акцентная полоска слева и/или выделение фона.
- **Tab bar:** фон в тон основному, вкладки компактные; выбранная — контрастнее; закрытие — крестик на hover.
- **Сообщения чата:** user — справа, акцентный фон; assistant — слева, фон `#2d2d2d`. Markdown (bold, italic, code, списки). Padding 12–16px.
- **Поле ввода:** многострочное, при необходимости автоувеличение высоты. Placeholder `#6e6e6e`, кнопка отправки с акцентом.
- **Кнопки:** Primary — синий фон, белый текст; Secondary — прозрачный фон, синий текст, border; Ghost — только текст. Высота 32–40px.
- **Карточки/панели:** фон `#2d2d2d`, border `#3a3a3a` или без, padding 16px, скругление 8px.

### 6.7 Состояния

Учитывать: **hover**, **focus**, **disabled**. При необходимости — **loading** (индикатор без блокировки всего экрана).

### 6.8 Иконки

Один набор — например **Material Icons** или **Lucide**. Не смешивать несколько наборов без необходимости.

---

## 7. Референсы и гибкость

**Основной референс:** Perplexity (чат, сайдбар, поле ввода, общий стиль). Дополнительно: Cursor IDE (сайдбар, тёмная тема), VS Code (структура табов).

**Не обязательно:** pixel-perfect копирование; сложные анимации на старте; кастомные иконки. Простота предпочтительна.

Документ живой — по мере разработки можно уточнять и дополнять.
