# Хранилище (Storage) в сценариях

Как в сценариях хранить и читать данные: ключ-значение с группировкой. Данные можно задавать через YAML-конфиги и синхронизировать с БД.

## Что такое storage

**Storage** — хранилище вида «группа + ключ → значение»:

- **Группа** (`group_key`) — логическая группа (например `settings`, `limits`).
- **Ключ** (`key`) — имя значения внутри группы.
- **Значение** — строка, число, bool, массив или объект (в т.ч. вложенные).

Одна запись однозначно задаётся парой: группа + ключ. В одной группе можно хранить много ключей.

## Конфигурация из YAML

Данные можно задать в **YAML-файлах**. По умолчанию используется папка `config/storage` (относительно корня проекта).

- Поддерживается **любая структура подпапок**: все `*.yaml` и `*.yml` читаются рекурсивно и объединяются.
- В каждом файле верхний уровень — ключи групп (`group_key`), значение группы — словарь `{key: value}`.

**Пример** `config/storage/settings.yaml`:

```yaml
settings:
  max_users: 100
  default_language: "ru"

limits:
  daily_requests: 1000
  max_file_size: 10485760
```

## Синхронизация с БД

- **При запуске** приложения плагин database один раз выполняет синхронизацию storage из YAML.
- **По требованию** — действие **`sync_storage`** (параметры не нужны).

**Логика:** для каждой группы, которая есть в объединённом конфиге, в БД сначала удаляется вся группа, затем в неё загружаются данные из конфига. Группы, которых нет в конфиге, в БД не изменяются.

## Действия

### sync_storage — синхронизировать из YAML

Без параметров. Перечитывает все YAML из папки `storage_config_dir` и обновляет в БД только те группы, которые присутствуют в конфиге. В ответе: `result`, `response_data.synced_groups` (количество обновлённых групп).

### get_storage — прочитать

Параметры:

- **group_key** — группа (точное совпадение).
- **key** — ключ (точное совпадение). Вместе с `group_key` — одно значение.
- **group_key_pattern** — паттерн по группе (LIKE: `%`, `_`). Если не задан `group_key`.
- **key_pattern** — паттерн по ключу (LIKE). Если не задан `key`.

Поведение:

- Заданы `group_key` и `key` → возвращается одно значение; если записи нет — в ответе будет `None` (в плейсхолдерах с None можно работать через fallback и т.п.).
- Задан только `group_key` → объект `{key: value}` по этой группе; при указании `key_pattern` — только подходящие ключи.
- Заданы паттерны или ничего → выборка по паттернам или все данные (с лимитом записей).

Результат действия попадает в кэш сценария (по контракту кэширования), обычно как `storage_values` или под заменяемым ключом. Вместе с ним возвращается **storage_processed_at** — дата последнего изменения (ISO 8601) в той же структуре: для одного значения — одна строка (или null), для группы — объект `{ key: "ISO дата", ... }`, для выборки по паттернам — `{ group_key: { key: "ISO дата" }, ... }`. Пример для группы: `{_cache.storage_processed_at.max_users}` — дата записи ключа `max_users`.

### set_storage — записать

Варианты:

- `group_key` + `key` + `value` — одна запись.
- `group_key` + `values` — объект `{key: value}` для группы.
- Только `values` — структура `{group_key: {key: value}}` для нескольких групп.

### delete_storage — удалить

- **group_key** обязателен.
- **key** необязателен: если указан — удаляется одна запись, иначе вся группа.

В ответе — `deleted_count` (сколько записей удалено; 0, если нечего было удалять).

## Типы значений

Поддерживаются значения, которые можно представить как JSON: строки, числа, bool, массивы, объекты (вложенные). При чтении они восстанавливаются из хранилища автоматически.

## Примеры

**Синхронизация из конфига:**

```yaml
- action: "sync_storage"
# Ответ: result, response_data.synced_groups
```

**Одно значение:**

```yaml
- action: "get_storage"
  params:
    group_key: "settings"
    key: "max_users"
# Результат в _cache (например _cache.storage_values). Если записи нет — None
```

**Вся группа:**

```yaml
- action: "get_storage"
  params:
    group_key: "settings"
```

**По паттернам:**

```yaml
- action: "get_storage"
  params:
    group_key_pattern: "set%"
    key_pattern: "max_%"
```

**Записать:**

```yaml
- action: "set_storage"
  params:
    group_key: "settings"
    key: "language"
    value: "ru"

- action: "set_storage"
  params:
    group_key: "limits"
    values:
      daily_requests: 1000
      max_file_size: 10485760
```

**Удалить группу:**

```yaml
- action: "delete_storage"
  params:
    group_key: "old_group"
```
