# Справочник по контрибьютам

Перечень **точек контрибьюта** и их атрибутов. Плагины объявляют в **contributes** в config.json; приложение запрашивает всё одним вызовом get_contributions и строит UI. Модель по аналогии с [VS Code Contribution Points](https://code.visualstudio.com/api/references/contribution-points), адаптирована под приложение (сайдбар, вкладки, действия по WebSocket).

**Иконки:** в полях **icon** (workspace, sidebar и т.д.) указывается идентификатор из набора приложения (например `"chat"`, `"settings"`, `"list"`). Плагин картинку не передаёт; хост подставляет иконку по id. Набор допустимых id фиксируется в этом разделе при включении отображения иконок.

---

## Архитектура расширения (фронт)

Вся логика контрибьюта сосредоточена в **frontend/src/contributions/** — по одной подпапке на точку контрибьюта; виджеты контента вкладки — в **contributions/workspace/widgets/**.

| Что | Где | Назначение |
|-----|-----|------------|
| **workspace** | contributions/workspace/ | Дефолты layout, обёртка WorkspaceLayout, маппинг по kind. Рендер контента вкладки по дескриптору content (виджеты). |
| **settings** | contributions/settings/ | Хелпер getSettingsSections(contributions): возвращает отсортированный список секций для вкладки «Настройки». Рендер в components/SettingsView.jsx (липкий заголовок, секции плагинов). |
| **sidebar** | contributions/sidebar/ | Хелпер getSidebarItems(contributions): объединяет встроенные пункты, пункты по workspace и contributions.sidebar; возвращает единый список для рендера. Sidebar в components/ только рисует переданный список. |
| **menus** | contributions/menus/ | Хелперы getHeaderMenuItems(contributions.menus), getTabContextMenuExtraItems(contributions.menus): возвращают списки пунктов контрибьюта; App объединяет их со встроенными и передаёт готовые списки в Sidebar и TabBar. |
| **modal** | App | Примитив приложения. Обработка события ui:show_modal и дескриптора (title, body, buttons) — в App; компонент Modal в components/ только рисует. |
| **виджеты** (list, form, tree) | contributions/workspace/widgets/ | Компоненты виджетов по дескриптору (ListWidget и т.д.). Рендер контента вкладки плагина по полю content.widget и опциям; вызывается из workspace-слоя или из компонента контента вкладки. |

**Правило разделения:** логика по точке контрибьюта (дефолты, слияние, маппинг) живёт в **contributions/<точка>/**; **components/** — только отрисовка по переданным данным. **App** вызывает хелперы из contributions/ (getSidebarItems, getHeaderMenuItems, getTabContextMenuExtraItems и т.д.), получает готовые списки или объекты и передаёт их в компоненты. Слияние «встроенное + контрибьют» не дублируется в компонентах. При добавлении новой точки или виджета — подпапка в contributions/ и при необходимости компонент в components/.

**Бэкенд:** контрибьют отдаётся в режиме **pass-through**: контейнер добавляет к объекту из config["contributes"] поле **pluginId** и включает его в агрегат без разбора полей. Фронт использует только известные ему атрибуты. Новые поля в контрибуте не требуют правок контейнера.

## Как разрабатывать и дорабатывать слой контрибьюта

Чтобы слой контрибьюта оставался предсказуемым и не размазывался по приложению:

1. **Одна точка — одна подпапка.** Вся логика по точке (дефолты, нормализация, слияние встроенного с контрибутом) живёт в `contributions/<точка>/`. Компоненты в `components/` не знают структуру контрибьюта: получают готовые списки/объекты и только рисуют.

2. **App — только оркестрация.** App запрашивает get_contributions, вызывает хелперы из contributions/ и передаёт результат в компоненты. Не дублировать слияние или разбор контрибьюта в App или внутри компонентов.

3. **Добавление новой точки контрибьюта:**  
   — описать схему и атрибуты в этом справочнике (новая секция);  
   — в контейнере: в `_get_all_contributions()` включать `config["contributes"]["<точка>"]` в агрегат (pass-through: объект + pluginId);  
   — на фронте: подпапка `contributions/<точка>/` с дефолтами и хелпером, возвращающим данные для рендера;  
   — в App: вызов хелпера, передача результата в компонент;  
   — в components: компонент принимает уже подготовленные данные, без парсинга контрибьюта.

4. **Добавление нового виджета контента вкладки:**  
   — описать дескриптор (content.widget и опции) в разделе «Контент вкладки (content)»;  
   — компонент виджета в `contributions/workspace/widgets/` или в `components/` при необходимости;  
   — рендер по content.widget в одном месте (например общий компонент контента вкладки плагина или модуль в contributions/workspace/);  
   — не дублировать виджет-специфичную логику в App или в нескольких компонентах.

5. **Чего избегать:** слияние «встроенное + контрибьют» и в App, и в компоненте; разбор контрибьюта по точкам внутри Sidebar/TabBar/других компонентов; добавление новых полей контрибьюта без описания в справочнике и без обработки в contributions/<точка>/.

## Структура contributes

Ключи в **contributes** — точки контрибьюта (workspace, menus, …). Значение — объект с атрибутами по схеме точки. Отсутствующий ключ = плагин не расширяет эту точку.

```json
"contributes": {
  "workspace": { "id": "...", "label": "...", ... },
  "settings": { "label": "...", "order": 10, "fields": [ ... ] },
  "sidebar": { "items": [ ... ] },
  "menus": { "sidebarHeader": [ ... ], "tabContextMenu": [ ... ] }
}
```

Дефолты: для каждого атрибута в точке задан дефолт; плагин переопределяет только нужные поля, остальное тянется из дефолта.

---

## settings (секции в общих настройках)

Один объект **settings** на плагин = одна секция во вкладке «Настройки» (открывается по шестерёнке). Все секции от плагинов отображаются в одной вкладке; порядок — по **order**, затем по pluginId.

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|--------------|----------|
| **label** | string | нет | Заголовок секции; по умолчанию — pluginId. |
| **order** | number | нет | Порядок секции (меньше — выше). По умолчанию 0; при равном order — по pluginId. |
| **fields** | array | да | Список полей (как у виджета settingsForm): объекты с **key** и опционально **label**. |

Сохранение: общая кнопка «Сохранить» в шапке вкладки и батч-сохранение по таймеру после изменений. Код: `frontend/src/contributions/settings/`, рендер секций в `components/SettingsView.jsx`.

Плагин может одновременно контрибьютить **workspace** (своя вкладка) и **settings** (секция в общих настройках).

---

## workspace (вкладка в основном контенте)

Один объект **workspace** на плагин = одна вкладка. Клик по пункту в сайдбаре открывает вкладку; контент — обёртка (layout) + содержимое по дескриптору (content) или заглушка.

**Заголовок вкладки** — это весь блок над контентом: текст заголовка (**title** или **label**), кнопки в шапке (например «Закрыть»), горизонтальная полоса и отступ перед основным контентом. Стили и отступы задаются общим шаблоном приложения (липкий заголовок), чтобы все вкладки (Настройки, AI, плагины) выглядели одинаково.

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|--------------|----------|
| **id** | string | да | Уникальный идентификатор вкладки (для сопоставления с открытой вкладкой, без дубликатов). Рекомендуется: plugin_id или суффикс. |
| **label** | string | да | Название в сайдбаре и в заголовке вкладки (таб). |
| **title** | string | нет | Заголовок внутри вида (липкий h2 в блоке заголовка). Если не задан, используется **label**. Рекомендуется задавать для единообразия. |
| **icon** | string | нет | Иконка (формат по соглашению приложения). |
| **layout** | object | нет | Обёртка контента: отступ сверху, тень, макс. ширина. См. ниже. |
| **content** | object | нет | Дескриптор контента (виджет + опции). Нет — заглушка. См. [Контент вкладки (content)](#контент-вкладки-content). |

### layout

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| topPadding | number \| string | 32 | Отступ сверху (px). |
| topShadow | boolean \| number | true (28px) | Градиент сверху; false — выкл. |
| contentMaxWidth | number \| string | "800px" | Макс. ширина контента (px или строка "80%"). |

Код дефолтов и обёртки: `frontend/src/contributions/workspace/`.

## Контент вкладки (content)

Задаётся **внутри** contributes.workspace полем **content**. Не отдельная точка контрибьюта: виджет — тип контента (list, form, tree), указывается в content и рендерится приложением.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| **widget** | string | Тип: `settingsForm`, `list`, далее `form`, `tree`. |
| остальное | — | Опции виджета (см. ниже). |

### Виджет settingsForm

Форма настроек плагина: поля из config.settings, отображаемые по списку в content.fields. Данные запрашиваются действиями get_plugin_settings / set_plugin_settings; при сохранении бэкенд эмитит событие `plugin:settings_changed:{plugin_id}` (только для этого плагина), плагин подписывается на него и обновляет свои атрибуты без перезапуска.

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|--------------|----------|
| **fields** | array | да | Список полей: объекты с **key** (ключ из config.settings) и опционально **label** (подпись; иначе берётся description из схемы). Порядок полей задаёт порядок в форме. Системные поля (например путь сохранения) можно не включать. |
| **settingsKey** | string | нет | Идентификатор плагина для запроса настроек; по умолчанию берётся pluginId вкладки. |

Типы полей в схеме плагина: `string`, `integer`, `boolean`, `array` (на форме — строка через запятую). Рендер: `contributions/workspace/widgets/SettingsFormWidget.jsx`; вызов из PluginWorkspaceView при content.widget === "settingsForm".

### Виджет list

Данные из action, колонки, действие по клику и меню по строке.

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|--------------|----------|
| **dataSource** | object | да | action (имя), payload?, responsePath? (путь к массиву в ответе). |
| **columns** | array | да | Элементы: key, label, format? (relativeTime, date). |
| **primaryAction** | object | нет | По клику по строке: openWorkspace (workspaceType, idKey) или callAction (action, payloadMap, confirm?). |
| **menuActions** | array | нет | Пункты меню по строке: label?, openWorkspace / callAction. |
| **sort** | object | нет | key, order (asc \| desc). |

Рендер: компонент в contributions/workspace/widgets/ или components/ по дескриптору; контент вкладки запрашивает данные по dataSource.action и отображает по columns. Бэкенд отдаёт content в get_contributions без изменений (pass-through).

### Виджеты form, tree

Схемы дескрипторов и реализация — в следующих итерациях; место размещения и правило те же (contributions/workspace/widgets/, один точок входа рендера по content.widget). Виджет **settingsForm** реализован (см. выше).

## sidebar (пункты списка левой панели)

Левая панель: сверху блок с иконкой настроек и выпадающим меню, ниже — **список пунктов** (кнопки). В списке: встроенные пункты (например «История чатов»), по одному пункту на каждый **workspace**-контрибьют (открытие вкладки), затем пункты точки **sidebar** (действие по клику без вкладки). Единый список формирует хелпер **getSidebarItems(contributions)** в contributions/sidebar/; App передаёт результат в Sidebar.

Структура в config: **contributes.sidebar** — объект с массивом **items**.

| Атрибут пункта (item) | Тип | Обязательный | Описание |
|------------------------|-----|---------------|----------|
| **id** | string | да | Уникальный в рамках плагина идентификатор пункта. |
| **label** | string | да | Текст на кнопке. |
| **icon** | string | нет | Иконка (формат по соглашению приложения). |
| **action** | object | да | При клике: **callAction** — имя действия и опционально payload; в перспективе **openWorkspace** (ссылка на вкладку). |

Пример: `"contributes": { "sidebar": { "items": [ { "id": "export", "label": "Экспорт…", "action": { "callAction": "export_data" } } ] } }`.

В ответе get_contributions: **contributions.sidebar** — массив пунктов от всех плагинов (каждый элемент с полем pluginId). Порядок в итоговом списке: встроенные → пункты workspace → contributions.sidebar. По клику на пункт sidebar вызывается действие (callAction).

## menus (пункты в выпадающих меню)

Добавление пунктов в существующие выпадающие меню. Места меню задаются идентификатором (**menuId**).

**Идентификаторы меню:**

| menuId | Где |
|--------|-----|
| **sidebarHeader** | Меню по клику на иконку настроек вверху сайдбара (встроенные пункты: «Настройки», «О приложении»). |
| **tabContextMenu** | Контекстное меню вкладки (три точки у вкладки; встроенный пункт «Переименовать»). |

Структура в config: **contributes.menus** — объект, ключи = menuId, значения = массивы пунктов.

| Атрибут пункта | Тип | Обязательный | Описание |
|----------------|-----|--------------|----------|
| **id** | string | да | Уникальный в рамках плагина идентификатор пункта. |
| **label** | string | да | Текст пункта меню. |
| **action** | string | нет | Имя действия API при выборе пункта. |

Пример: `"contributes": { "menus": { "sidebarHeader": [ { "id": "docs", "label": "Документация…", "action": "open_docs" } ] } }`.

В ответе get_contributions: **contributions.menus** — объект, ключи = menuId, значения = массивы пунктов от всех плагинов (каждый пункт с pluginId). App вызывает getHeaderMenuItems(contributions.menus) и getTabContextMenuExtraItems(contributions.menus), объединяет результат со встроенными пунктами и передаёт готовые списки в Sidebar и TabBar.

## Модальное окно

Не точка контрибьюта: примитив приложения. Показ по событию **ui:show_modal** с бэкенда (`api_bus.emit("ui:show_modal", descriptor)`); событие пробрасывается во фронт (EVENTS_TO_BRIDGE в ws_server).

Дескриптор (данные события):

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|--------------|----------|
| **title** | string | да | Заголовок модалки. |
| **body** | string | нет | Текст в теле. |
| **buttons** | array | нет | Кнопки; каждая — объект см. ниже. Если пусто — одна кнопка «Закрыть». |

Элемент **buttons[]**:

| Атрибут | Тип | Описание |
|---------|-----|----------|
| **label** | string | Текст кнопки. |
| **action** | string | Имя действия при нажатии. |
| **payload** | object | Опциональный payload для вызова действия. |
| **danger** | boolean | true — стиль «опасное действие». |
