# Гайд по событиям

Справочник атрибутов, попадающих в сценарии с событиями. По мере добавления плагинов (Telegram, Discord, Slack и др.) сюда дополняются типы, источники и атрибуты.

## Принцип именования

- **Общие/унифицированные** атрибуты — префикс `event_`, чтобы не смешиваться с уникальными полями источников и не перезатирать их при мерже params во сценарии: `event_type`, `event_source`, `event_text`, `event_timestamp` и т.д.
- **Уникальные для источника** — формат `источник_атрибут`: `app_chat_id`, `telegram_chat_id`, `discord_channel_id`. Так в одном сценарии не конфликтуют идентификаторы разных систем.
- **Плагины:** отдают в событие те же имена атрибутов, что и принимают в своих действиях. В сценарии можно прокидывать значение из события в действие без переименования (например `app_chat_id: "{app_chat_id}"`).

## Типы событий (event_type)

Унифицированные типы для всех источников:

| event_type | Описание |
|------------|----------|
| `message` | Текстовое (или с медиа) сообщение от пользователя/системы |
| *(далее по плагинам)* | `callback`, `member_joined`, `member_left` и т.д. |

## Источники (event_source)

| event_source | Описание |
|--------------|----------|
| `app` | Сообщение из встроенного чата приложения (фронт) |
| *(далее по плагинам)* | `telegram`, `discord`, `slack` и т.д. |

## Общие атрибуты (event_*)

Доступны во всех событиях, где применимо:

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `event_type` | string | Тип события (`message`, …) |
| `event_source` | string | Источник (`app`, `telegram`, …) |
| `event_text` | string | Текст сообщения (если есть) |
| `event_timestamp` | integer | Unix-время события (секунды) |

В scheduled-сценариях и при других синтетических событиях часть полей может отсутствовать.

---

## Атрибуты по источнику

### event_source: app

События из встроенного чата приложения (плагин **chats**). Фронт отправляет действие `chat_submit_message`; плагин сохраняет сообщение и передаёт payload в сценарии.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `event_type` | string | `"message"` |
| `event_source` | string | `"app"` |
| `event_text` | string | Текст сообщения пользователя |
| `event_timestamp` | integer | Unix-время (секунды) |
| `app_chat_id` | integer | ID чата (передаётся напрямую в действия плагина чата) |
| `app_message_index` | integer | Индекс сохранённого сообщения в чате (удобно для ответа через `send_chat_message` и отслеживания) |

---

### Другие источники (будущие)

При добавлении плагинов (Telegram, Discord, Slack и т.д.) здесь появятся секции с атрибутами вида `telegram_chat_id`, `telegram_user_id`, `discord_channel_id` и т.д., чтобы в сценариях не путать идентификаторы разных систем.

---

## Scheduled-сценарии

Сценарии по расписанию (`schedule`) запускаются синтетическим событием с фиксированным типом и источником. Атрибуты пользователя/чата (`event_text`, `app_chat_id` и т.д.) отсутствуют.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `event_type` | string | `"scheduled"` |
| `event_source` | string | `"schedule"` |
| `event_timestamp` | integer | Unix-время запуска (секунды) |
| `scheduled_at` | string | Дата/время запуска (ISO) |
| `scheduled_scenario_id` | integer | ID сценария в кэше |
| `scheduled_scenario_name` | string | Имя сценария |

Для отправки в конкретный чат указывайте целевой идентификатор в параметрах действия (например `app_chat_id` в действии плагина чата).

---

## Системные атрибуты контекста выполнения

Во время выполнения сценария движок дополняет контекст (данные, доступные в плейсхолдерах) следующими атрибутами. К ним можно обращаться в `params` последующих шагов, например в сценариях обработки ошибок.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `last_error` | object | Объект ошибки последнего шага, если действие вернуло `result: "error"`. В плейсхолдерах: `{last_error.message}`, `{last_error.code}`. Пример: `{last_error.message\|fallback:Неизвестная ошибка}` |
| `last_result` | string | Результат последнего выполненного действия: `success`, `error`, `abort`, `break` и т.д. Используется для переходов (transition) и условий. |
| `scenario_chain` | array (string) | Цепочка имён сценариев в текущем вызове (например при `jump_to_scenario`). Полезно для отладки и логирования. |
| `_cache` | object | Кэш сценария: данные, накопленные из `response_data` действий (плоско или по `_namespace`). В плейсхолдерах: `{_cache.key}`, `{_cache.tools.name.field}`. Подробнее — [Плейсхолдеры](PLACEHOLDERS.md). |
| `_async_action` | object | Служебные данные асинхронных действий (координация `async`-шагов и `wait_for_action`). Обычно не используется в плейсхолдерах сценариев. |

**Структура `last_error`** (заполняется движком из ответа действия):

| Поле | Тип | Описание |
|------|-----|----------|
| `code` | string | Код ошибки (например `VALIDATION_ERROR`, `API_ERROR`, `CONFIG_ERROR`). |
| `message` | string | Текст ошибки для отображения пользователю или логу. |

Пример использования в сценарии ошибки:

```yaml
- action: "send_chat_message"
  params:
    text: "❌ Ошибка: {last_error.message|fallback:Неизвестная ошибка}"
```
